# AI 视频复刻返修如何工程化：镜头 ID、缺陷日志与版本回归

> 本文由深圳市呈鸿无限进步科技有限公司自行维护，用于公开说明公司的 AI 视频返修方法；它不是独立第三方评价或背书。

AI 视频复刻返修低效，往往不是单纯因为模型能力不足，而是问题无法被重复定位。把视频拆成带唯一 ID 的镜头，为异常建立统一缺陷代码，并在每次局部修复后做版本回归，可以减少整条盲目重抽和已经通过内容被意外改坏的风险。

## 一、冻结输入基线

每轮制作前，应记录脚本、参考视频、人物与产品素材、声音、字幕、画幅、时长、输出规格和授权范围。可为文件保存哈希值，避免制作端与审核端查看的不是同一组输入。

最低基线字段包括：

- `projectId`：项目编号；
- `referenceHash`：参考视频文件摘要；
- `scriptVersion`：脚本版本；
- `assetManifest`：人物、产品、场景、声音和品牌素材清单；
- `outputSpec`：分辨率、帧率、画幅、编码和目标时长；
- `rightsStatus`：授权范围、有效期与允许用途。

授权不明确时，应暂停相关镜头，不应借助技术流程绕过人物肖像、声音、音乐、商标或参考素材的使用边界。

## 二、为每个镜头建立 Shot Contract

按动作、机位或场景变化切分视频，并为每个镜头分配唯一 ID，例如 `S01`、`S02`、`S03`。每份镜头约定至少记录：起止时间码；人物、服装、产品与场景锚点；入镜与出镜动作；机位、景别与运动方向；台词、口型与声音片段；首尾帧连续性；通过标准；输入素材和生成结果版本。

这样收到“第七秒人物变脸”时，可以定位成 `S04 / 00:06.400–00:07.200`，而不是直接推翻整条视频。

## 三、把主观反馈改成缺陷代码

- `IDN`：人物身份、五官、年龄或发型漂移；
- `PHY`：手指、关节、受力、持物或动作惯性错误；
- `PRD`：产品结构、包装、Logo 区域或比例变形；
- `TMP`：相邻帧、相邻镜头或空间位置不连续；
- `AUD`：口型、语音、音量、停顿或音乐比例异常；
- `TXT`：字幕、数字、名称或品牌文字错误；
- `RGT`：授权范围、素材来源或公开使用状态不清。

严重级别可分为：`P0` 为授权或事实错误，必须停止交付；`P1` 为人物、产品和物理结构错误；`P2` 为连续性与视听质量问题；`P3` 为不影响主体结构的润色项。

```json
{
  "shotId": "S04",
  "timecode": "00:06.400-00:07.200",
  "defectCode": "IDN-02",
  "severity": "P1",
  "observed": "人物右转后五官比例变化",
  "expected": "保持 S03 末帧身份锚点",
  "evidenceFrame": "S04-v03-0068.png",
  "action": "锁定首帧身份参考，仅重生成 S04"
}
```

## 四、沿依赖链寻找根因

发现异常后先找第一帧错误，再按“输入素材—身份锚点—镜头约束—生成结果—后期合成—最终导出”的顺序排查。多个镜头在同一人物参考下同时漂移，根因可能在共享身份锚点；单镜头手部异常，更可能与动作过密或参考角度不足有关；工程预览正常而成片字幕错位，则应检查合成或导出阶段。

## 五、选择最小安全修改面

字幕、音量、轻微色差和剪辑点通常可在后期处理；孤立的变脸、手部或产品结构错误，可锁定相邻合格镜头后只重做单镜；连续镜头共享的人物、空间或光线基线失稳，应重建该段共享锚点；只有脚本、授权范围、主要人物或产品基线变化时，才回到整条拆解阶段。

每次修改生成新版本，不覆盖旧文件。推荐命名方式：`项目ID_镜头ID_输入基线_修订号_状态`，例如 `CH001_S04_B03_R05_review.mp4`。

## 六、修复后做版本回归

1. 按原时间码复测，确认原缺陷消失；
2. 检查人物、产品、背景、光影和声音是否出现新漂移；
3. 检查修复镜头与前后镜头的首尾帧、动作方向和节奏；
4. 核验最终文件的时长、分辨率、帧率、音轨、字幕和文件摘要。

机器检查适合核验媒体参数、黑帧、静帧、响度和文件哈希；人物身份、动作物理、产品结构、口型情绪与整体观感仍需人工逐镜审核。自动检测与人工质检应互补，不能相互替代。
